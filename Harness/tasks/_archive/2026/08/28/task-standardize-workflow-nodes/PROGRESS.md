## RCA Summary

The current failures came from multiple layers:

- Architecture instability: `WorkflowRoute.tsx` centralizes too many graph, UI, persistence, terminal, overlay, and editor concerns.
- Interaction detail bugs: Explorer, canvas, node, edge, and pane gestures lacked a single ownership model.
- API contract gaps: the file read endpoint existed, but the full file pipe for browser previews and agent-readable content refs was incomplete.
- Persistence instability: pointermove and transient edge offset changes could become durable graph-map writes.
- Overlay instability: toast/menu/panel z-index was not a declared layer system.
- Performance instability: exact zoom fanout, eager previews, deep scene comparisons, and broad state effects could cause rerender storms.
- React crash: user reported React minified error #185, treated as a P0 update-loop failure until browser evidence cleared it.
- W5 connection-state RCA: prior code mixed endpoint order, runtime direction, semantic relation, and display label into one loose edge shape. That let UI labels like `markdown -> context` leak into `relation`, let reverse duplicate edges coexist, and made small-node/context snapshots disagree with backend runtime state.
- W5 similar-risk class: any state crossing backend snapshot, graph-map persistence, ReactFlow render state, and agent-readable context can drift when it has no single canonical schema, no normalizer, and no reverse-route regression tests.
- W5 prevention standard: connection state is canonicalized at store/API boundaries; `from/to` are endpoint ordering/render metadata only; default workflow links are bidirectional; runtime readers expose `endpointRole`; duplicate checks use unordered endpoint pairs; labels are presentation-only; docs/templates must be updated with any state-contract change.
- W6 connection-handle RCA: W5 made edges bidirectional but still let Markdown/Excalidraw inherit split input/output assumptions in some API paths and UI handle paths. ReactFlow needs physical side handles for geometry, while agents and graph contracts need semantic resource ports. Mixing those two concepts let handles jump sides or appear duplicated.
- W6 state/edit RCA: fullscreen component editors kept separate draft state, but backend revision refreshes could still overwrite local dirty drafts. Settings and double-click behavior also used generic node defaults instead of node-kind-specific UX.
- W6 prevention standard: resource nodes declare `semanticPort + physicalHandles`; physical handles are render metadata only; every graph/API/frontend import-export boundary must normalize handles and relation; component editors must guard dirty fullscreen drafts by revision; double-click behavior is node-kind-specific and must be tested.
- W6 future-node standard: one-way semantics belong to explicit event-source nodes such as Timer/Trigger/GitHub, not resource nodes. MCP and Skills start as capability-provider nodes attached to Agents; group/subgraph boundary-port serialization needs a spec before implementation.
- W7 catalog standard: create-node surfaces must be generated from one registry. Future node types stay visible but disabled as `planned` until runtime/storage/port/settings/action/test contracts exist, preventing UI-only nodes from drifting away from backend and agent-readable state.
- W8 capability-hub standard: discovery can ship before attachment only when it is read-only metadata, path-safe, body-free, and clearly separated from runtime node creation. Skill/MCP are Agent-attached capability providers; the Agent remains the executor.
- W8 recurrence guard: a catalog item that opens a Hub must advertise `data-node-action="open-hub"` and stay read-only when no Agent target exists. Attach/create may only enable after the backend attachment contract, Agent context fields, and tests exist. MCP listing must start as no-spawn/no-secret metadata, not server startup or credential probing.
- W9 Agent capability standard: Skill attachment is an Agent config mutation, not a Skill node lifecycle. No-target Hubs stay read-only; targeted Hubs PATCH the Agent config with deduped `skills` and `skillPolicy: "manual"`; Agent context must expose attached skills as `connectedCapabilityRefs`/`effectiveSkills` with executor `agent`.
- W10 recurrence RCA: app-level bidirectional semantics were correct, but the UI did not provide ReactFlow target-type hit handles for resource ports and tests relied too much on semantic intent actions. That left the real manual drag path under-tested.
- W10 prevention standard, superseded by W11 port correction: resource-port
  tests must include real browser handle dragging and bare `left`/`right`
  physical aliases must be preserved before semantic fallback at
  frontend/backend boundaries. W11 bans hidden overlapping resource handles.
- W10 future-edge standard: default resource and capability links are still bidirectional. Directed edges are a separate future event contract for Timer/Trigger/GitHub trigger nodes, not a retroactive change to Markdown, Excalidraw, Skills, or MCP metadata links.
- W10 MCP standard: MCP discovery now has a no-spawn/no-secret metadata route. MCP attach/create remain gated until Agent config mutation, permission, audit, and runtime context contracts are implemented and tested.
- W11 correction RCA: the W10 hidden target-hit implementation made the visual count correct but left duplicate DOM handles with the same physical id. In dense graphs that can still produce ambiguous hit-testing and wrong-node snap behavior.
- W11 prevention standard: a bidirectional physical side is one visible DOM handle that can start and receive connections. Hidden overlapping source/target handles are banned unless a future canvas adapter explicitly proves they cannot affect hit-testing.
- W11 event-edge standard: Timer is the first real directed event-source node. `direction: "source-to-target"` is valid for Timer event emission only; default resource/capability/agent links remain bidirectional.
- W12 capability-node RCA: Skill group had to move through every state boundary at once: backend store, workflow runtime snapshot, graph-map normalization, frontend layout/rendering, Hub creation affordance, and Agent context. Leaving any boundary UI-only recreates the same class of missing thumbnail/context/connection bugs seen with resource nodes.
- W12 prevention standard: a Hub action that creates a node must have a runtime adapter, backend-owned state, snapshot merge path, renderer, Agent-readable context fields, API tests, browser tests, and a rebuilt UI dist before Playwright acceptance. Catalog `open-hub` status is not equivalent to runtime readiness.
- W13 MCP connector standard: MCP connector creation is metadata-only and backend-resolved by `mcpServerId`. The frontend must not send raw MCP server config, and the backend must not persist raw args/env values/full command paths/raw config/tool bodies/absolute paths or spawn/probe MCP servers during list, create, context read, settings, or preview.
- W13 capability-context standard: MCP connectors contribute connected capability refs but do not become `effectiveSkills`; Skill groups can affect `effectiveSkills`, MCP server names cannot. Direct MCP attach/tool invocation requires a separate permission/audit/runtime contract.
- W14 Advanced Timer standard: Timer is still an event/control node, not a resource node. It exposes a directed event output for heartbeat delivery and a separate Agent-to-Timer `control` edge for mutable actions such as interval changes, WDT ack/reset, enable/disable, and mode changes.
- W14 Timer safety standard: while/loop/task timer modes are declarative state only. Runtime tick computes due events from bounded metadata and never evaluates user code from node settings.
- W14 Goal-node standard: Goal nodes are task-state views plus proposal sidecars. Agent nodes may request completion and feed/ack WDT through graph context, but task `STATE.json` completion remains a human/runtime closeout action until a separate authority contract exists.
- W15 Goal action standard: Agent-authored Goal mutations require an existing bidirectional `goal` edge between the Agent and Goal node. Unconnected actors are rejected with `GOAL_EDGE_REQUIRED`.
- W15 canvas-menu standard: blank-canvas context menus must be handled at document capture scope because ReactFlow/pan handlers can swallow pane-level contextmenu propagation. The fallback must be canvas-scoped and must not fire from nodes, handles, edges, Explorer, controls, inputs, or floating panels.
- W16 operation-language standard: single-click selects, right-click opens lightweight menu/settings, and double-click opens the node's primary workbench. Agent opens terminal, Markdown/Excalidraw open enlarged editors, Timer opens expanded schedule configuration, and Goal opens expanded Goal editing.
- W16 Timer edit standard: expanded Timer edits save through typed `timer.configure`; UI must preserve every supported schedule mode (`manual`, `once`, `interval`, `cron`, `loop`, `adaptive`, `watchdog`, `while`, `task`) and must not coerce unknown-to-the-editor modes on save.
- W16 Goal edit standard: user-owned Goal edits write editable metadata to the backend Goal sidecar via `goal.update`, while task `STATE.json` remains the task source reference. `goal.update` must not accept status/phase/gate closeout fields. Agent-authored `goal.update` still requires a bidirectional `goal` edge when `actorNodeId` is present.
- W18 Agent-control standard: Agent-authored graph mutations must go through typed Main-Agent `agent.*` actions and append bounded sanitized operation records. Frontend control visuals must derive only from `workflow.operations.recent[]`; semantic browser graph intents must issue one semantic mutation request and return operation metadata.
- W23 product standard: the near-term product should sell the Agent-operable observable workflow canvas and context-bound Agent durable IO. Do not sell unattended scheduler/orchestrator, arbitrary MCP invocation, external webhook triggers, or Agent-team scheduling as release-ready until their runtime contracts exist.
- W23 relation standard: Goal authority edges are canonical `goal`; `wf-bridge/goal` may appear as a legacy/namespaced alias but must normalize to the same backend permission semantics before any Agent-authored Goal action is evaluated.
- W23 testing standard: an Agent-node E2E must verify durable state changes in connected nodes by revision/content, not only terminal prose. Browser-plugin evidence must be labeled unavailable when `iab` cannot be acquired.
- W24 graph-binding standard: wf-ui-created Agent sessions must persist as real workflow graph nodes before node init and PTY launch; snapshot-only virtual Agent nodes are invalid because connect/delegate/read APIs resolve against the backend workflow map.
